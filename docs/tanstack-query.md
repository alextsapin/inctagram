# TanStack Query

TanStack Query используется для получения, кэширования и обновления данных
с сервера на клиентской стороне. HTTP-запрос выполняет функция API, которую
передаём библиотеке: можно использовать обычный `fetch`.

## Как подключено

1. Установлена зависимость `@tanstack/react-query` через pnpm. Изменения
   зафиксированы в `package.json` и `pnpm-lock.yaml`.
2. В `src/shared/api/queryClient.ts` создана функция `createQueryClient` с общими
   настройками запросов. Эта инфраструктура не зависит от бизнес-сущностей,
   поэтому находится в слое `shared`.
3. В `src/app/providers/QueryProvider.tsx` создан клиентский провайдер на уровне
   приложения (FSD). Он предоставляет QueryClient вложенным компонентам.
4. Провайдер подключён в корневом `app/layout.tsx` внутри `body`, чтобы хуки
   TanStack Query были доступны клиентским компонентам всех страниц.
5. Экспорты доступны через `index.ts`: `@/shared/api` и `@/app/providers`.

QueryClient создаётся в провайдере ленивым инициализатором:

```tsx
const [queryClient] = useState(createQueryClient);
```

В `useState` передаём функцию, а не результат её вызова. React сохраняет
полученный клиент на время жизни провайдера и не создаёт его при каждом
повторном рендере. В режиме разработки Strict Mode может вызвать инициализатор
дважды для проверки его чистоты; сохраняется один экземпляр.
Корневой layout сохраняет провайдер при обычной навигации между страницами,
поэтому его кэш доступен после переходов. После полной перезагрузки страницы
кэш в памяти создаётся заново; сохранение в `localStorage` не настроено.

## Настройки кэша

-   `staleTime` — 60 секунд. В течение этого времени полученные данные считаются
    свежими. Это общая стартовая настройка, которую можно переопределить
    для конкретного запроса.
-   Истечение `staleTime` не удаляет данные и само по себе не запускает запрос
    по таймеру. Для периодического обновления существует `refetchInterval`.
-   Остальные настройки оставлены стандартными: неактивный кэш в браузере
    удаляется через 5 минут (`gcTime`); неудачные запросы повторяются до 3 раз;
    устаревшие данные обновляются при монтировании, возвращении фокуса
    и восстановлении сети.

## Как добавлять запросы

Функции API и ключи запросов размещаем в `api` соответствующего слайса
`entities` или `features`. Общий HTTP-клиент, если понадобится, размещаем
в `shared/api`.

Хуки `useQuery`, `useMutation` и `useQueryClient` вызываем в клиентских
компонентах или их кастомных хуках. Компонент, задающий клиентскую границу,
должен иметь `'use client'` в начале файла.

Для получения данных передаём в `useQuery`:

-   `queryKey` — уникальный ключ данных в кэше. Все параметры, влияющие на ответ,
    включаем в ключ: например, `['posts', { page }]` или `['profile', userId]`.
-   `queryFn` — функцию, которая возвращает данные или выбрасывает ошибку.
    При использовании `fetch` проверяем `response.ok` самостоятельно.

Одинаковые ключи используют общую запись кэша. Для отображения результата
используем `data`, для отсутствия успешных данных — `isPending`, для ошибки —
`isError` и `error`. `isFetching` показывает выполнение запроса, включая
обновление в фоне, когда данные уже есть.

Изменения данных на сервере выполняем через `useMutation`. После успешной
операции обновляем соответствующий кэш с помощью
`queryClient.invalidateQueries({ queryKey })` или `queryClient.setQueryData`.
Клиент внутри компонента получаем через `useQueryClient()`.

## Особенности Next.js

Используем обычные клиентские запросы через `useQuery`. Серверный prefetch,
`dehydrate` и `HydrationBoundary` не настроены. Конкретные endpoints добавляются
по задачам; базовая настройка сама по себе не отправляет запросы к backend.

Корневой layout остаётся серверным компонентом, а провайдер использует
`'use client'`, поскольку ему нужны React Context и `useState`.
Это сохраняет стандартное предварительное формирование HTML в Next.js.
Директива `'use client'` не отключает такой рендеринг, но обычный `useQuery`
без серверного prefetch получает данные после подключения компонента в браузере.

Если ТЗ потребует серверное получение данных для конкретной страницы,
интеграцию серверной загрузки с клиентским кэшем добавляем отдельной задачей.
